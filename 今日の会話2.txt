では、「なぜイテレータという概念が生まれ、そこから数学の概念にどうつながるのか」を
少し長めのストーリーとして整理します。

専門用語は出てきますが、できるだけ「自然な流れ」で出てくるようにします。

⸻


すべては「繰り返し」から始まる


ある日、プログラマーがこう書きます。

for x in collection:
    process(x)

これはとても自然です。

でも少し考えると不思議です。

collection は実は色々なものになり得ます。
	•	配列
	•	linked list
	•	tree
	•	データベース結果
	•	ファイル
	•	ネットワークストリーム
	•	無限列

なのに同じ書き方です。

つまり言語は

「順番に取り出す」という操作を統一している

のです。

この統一された仕組みが

イテレータ (iterator)

です。

⸻


イテレータの中で起きていること


イテレータは簡単に言うと

「次の要素を返す機械」

です。

イメージ

collection
    ↓
iterator
    ↓
next()

next() を呼ぶと

1
2
3
4

のように値が出てきます。

⸻


ここで不思議なことが起きる


next() を見てください。

next()

入力がありません。

でも

next() → 1
next() → 2
next() → 3

出力が変わります。

普通の数学の関数は

f(x) = x + 1

のように

同じ入力 → 同じ出力

になります。

でも next() は違います。

なぜでしょう？

⸻


答え：状態がある


答えは

内部状態 (state)

です。

例えば配列 [1,2,3,4] を考えます。

イテレータの内部には

state = 現在位置

があります。

例えば

state = 0

next() を呼ぶと

value = array[state]
state = state + 1
return value

つまり

state: 0 → 1 → 2 → 3

と進みます。

⸻


これを数学で書く


この動きを数学で書くとこうなります。

state → (value, new_state)

つまり

next : S → (A , S)

意味

S = 状態
A = 出力される値

例

0 → (1,1)
1 → (2,2)
2 → (3,3)

これが

イテレータの数学的モデル

です。

⸻


でもまだ問題がある


列の最後に到達するとどうなるでしょう。

1
2
3

このあと

next()

は

値がない

になります。

そこで登場するのが

Option 型

です。

⸻


Option


Option は

Some(value)

または

None

です。

つまり

値がある
または
値がない

という型です。

するとイテレータの式は

next : S → Option(A , S)

になります。

意味

状態
↓
値がある → (value, 新しい状態)
値がない → None



⸻


ここで数学者が気づく


この式

S → Option(A,S)

は実は既に知られている形でした。

それが

unfold

です。

⸻


unfold とは何か


unfold は

状態から順番にデータを作る仕組み

です。

例えば自然数列を作るとします。

最初の状態

state = 1

ルール

n → (n , n+1)

すると

1
2
3
4
5
...

という列が生成されます。

これが

unfold

です。

⸻


unfold = iterator


ここが重要です。

unfold の型

S → Option(A,S)

イテレータの型

next : S → Option(A,S)

完全に同じです。

つまり

iterator = unfold

です。

イテレータは

状態を少しずつ進めながら
列を生成する装置

なのです。

⸻


fold が登場する


ここで逆の操作が出てきます。

[1,2,3,4]

を

10

にする。

つまり

データ → 1つの値

これが

fold

です。

例

sum
product
count
max



⸻


fold と unfold


この2つは対称です。

unfold
state → list

fold
list → value

つまり

生成
vs
集約

です。

⸻


モナドが登場する理由


ここでプログラマーは別の問題にぶつかります。

計算にはいろいろな種類があります。

例えば

値がない可能性
エラー
非同期
状態
複数の値

普通の関数

A → B

では扱いにくいのです。

そこで

計算を包む型

が登場します。

それが

M<A>

です。

例

Option<A>
Result<A>
Future<A>
List<A>



⸻


モナド


モナドは

計算をつなぐルール

です。

例えば Option

Some(3)
 → Some(4)
 → Some(5)

途中で

None

になれば

そのまま None

になります。

この

安全に計算を合成する仕組み

が

モナド

です。

⸻


iterator とモナド


イテレータも実は

状態付き計算

です。

state → (value , state)

これは

State モナド

と非常に近い構造です。

⸻


algebra と coalgebra


最後に少しだけ数学の話です。

数学では

algebra

構造をまとめる

例

fold

list → value



⸻

coalgebra

構造を生成する

例

unfold

state → list



⸻

つまり

fold = algebra
unfold = coalgebra

です。

そして

iterator

は

coalgebra の具体例

です。

⸻


この物語の核心


今回のストーリーは

すべてこの式に集約されます。

next : S → Option(A,S)

この式が

Iterator
State machine
Unfold
Generator
Stream
Coalgebra

すべてを説明しています。

⸻

もしよければ次に、

「iterator → generator → coroutine → async」

が全部同じ構造になる話を
かなり直感的に説明できます。

これはプログラミングの抽象の中でも かなり核心の部分です。
